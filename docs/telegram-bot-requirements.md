# Требования к Telegram-боту SmetaProAI (черновик архитектуры)

Зафиксировано со слов Маши 2026-09-04, для проектирования архитектуры бота перед тестовым запуском.

1. Бот должен быть реально запущен в Telegram (`@SmetaProAI_bot`, хэндл зарегистрирован Машей) — не описание, а рабочий инстанс для тестирования.
2. Приём заданий текстом — Маша пишет боту словами, как обычному собеседнику (например, «сбить сосульки с крыши 120 п.м., работа только с вышки»).
3. Приём заданий голосом — бот должен распознавать голосовые сообщения (нужен speech-to-text).
4. Приём файлов — Word, Excel, PDF: бот должен уметь их прочитать и проанализировать содержимое (задание, данные по объекту, возможно готовая смета).
5. По присланным данным/заданию — бот составляет черновик сметы (подбор расценок из базы СН → сборка сметы, см. [[smeta-rate-picker]], [[smeta-compiler]]).
6. Проверка готовых смет — Маша сможет прислать боту уже готовую смету (файлом), бот должен её проверить на полноту и корректность (см. [[smeta-validator]]).
7. План запуска: собрать первую рабочую версию → тестовый прогон на реальных задачах → калибровка по результатам теста.

## Дальше по архитектуре — нужно продумать отдельно

- Технологический стек бота (какой фреймворк/библиотека для Telegram).
- Речь → текст: какой сервис/модель для голосовых. **Не выбрано**, обсудим позже (варианты на столе: Yandex SpeechKit — лучше понимает русский, оплата в рублях; OpenAI Whisper — можно бесплатно локально, настройка сложнее).
- Разбор файлов: Word/Excel/PDF → извлечение текста и структурированных данных (таблиц) из смет.
- Формат ответа бота (черновик сметы — файлом Excel/Word или текстом в чате) и куда сохранять (`reports/`).
- Как бот будет обращаться к базе СН (прямой доступ к `data/sn2012_2026.sqlite` из кода бота).
