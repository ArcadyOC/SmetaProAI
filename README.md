# SmetaProAI — база СН-2012

Официальный сборник стоимостных нормативов Москвы (СН-2012) в виде SQLite плюс исходные PDF с mos.ru.
Сборник переиздаётся каждый квартал, в репозитории лежит актуальный выпуск и скрипты, которые находят и подхватывают новый.

**Текущий выпуск:** уровень цен **01.07.2026** (выпуск 8, «СН-2026»), утверждён распоряжением ДЭПР от 25.06.2026 № ДПР-Р-15/26.

## Источник

- Карточка документа: https://www.mos.ru/depr/documents/cenovaya-politika/cenoobrazovanie-v-gorodskom-khozyaistve/cenoobrazovanie-v-gorodskom-khozyaistve-2026-god/view/344770220/
- Портал сборника: https://ac.mos.ru/cn-2012/

Берём только публичные PDF с портала Москвы. Коммерческие базы в форматах Smeta.RU и Гранд-Смета сюда не входят.

## Быстрый старт

```powershell
pip install -r requirements.txt
python scripts/build_db.py          # собрать базу из PDF (~2 минуты)
python scripts/search.py отопление  # искать
```

Готовая база в git не хранится (файл ~100 МБ), её можно либо собрать командой выше, либо скачать из [Releases](https://github.com/ArcadyOC/SmetaProAI/releases) и положить в `data/db/`.

## Обновление раз в квартал

Сборник выходит на 01.01, 01.04, 01.07 и 01.10. После начала квартала:

```powershell
python scripts/update.py --check   # только проверить, есть ли новый выпуск
python scripts/update.py           # найти, скачать, пересобрать, сравнить
```

`update.py` последовательно делает всё: ищет свежий документ на mos.ru, качает PDF, собирает новую базу и пишет отчёт об изменениях относительно прошлого квартала в `data/reports/`.

Как работает автопоиск: у API mos.ru нет рабочего поиска (любой `filter[...]` отвечает 500, а `q=` игнорируется), зато работает сортировка. Поэтому скрипт идёт по списку документов от свежих к старым до даты последнего известного выпуска и ищет заголовок «Сборник СН-2012 в текущих ценах по состоянию на ДД.ММ.ГГГГ». Между кварталами это примерно 4–5 тысяч документов и полминуты работы. Перед загрузкой найденный документ проверяется на полноту: должно быть не меньше 50 PDF, среди них главы `SN_gl*` и материалы `sn21*`, иначе скрипт останавливается и ничего не перезаписывает.

Отдельные шаги, если нужно вручную:

```powershell
python scripts/fetch_release.py --doc-id 344770220 --order-doc-id 344769220
python scripts/build_db.py
python scripts/diff_releases.py --old 01.04.2026 --new 01.07.2026
```

## Структура

| Путь | Содержимое |
| --- | --- |
| `data/pdf/` | 97 PDF текущего выпуска (~262 МБ) |

| `scripts/search.py` | Поиск по базе |
| `scripts/update.py` | Всё вместе одной командой |

## Схема базы

- `documents` — файлы сборника (глава, номер сборника, URL, SHA-256)
- `rates` — стоимостные нормативы: шифр, наименование, измеритель, прямые затраты, зарплата, машины, материалы, трудозатраты
- `rate_resources` — ресурсы в составе расценки
- `materials` — глава 21, материалы
- `machines` — глава 22, машины и механизмы
- `pages` — полный текст каждой страницы PDF
- `rates_fts` — полнотекстовый поиск по расценкам
- `meta` — уровень цен, ссылки на источник, счётчики

Шифр внутри разных сборников повторяется, поэтому уникальный ключ — `full_code`, например `СН-2012.1-1:1-3101-1-1/1`.

## Примеры

```powershell
python scripts/search.py "1-3101-1-1/1"
python scripts/search.py грунт --limit 5
python scripts/search.py битум --kind materials
python scripts/search.py экскаватор --kind machines
```

```sql
SELECT full_code, name, unit, direct_cost, wages, labor_hours
FROM rates
WHERE name LIKE '%грунт%' AND direct_cost IS NOT NULL
LIMIT 20;
```

В текущем выпуске: 33 900 расценок (33 371 с ценой), 25 877 ресурсов, 10 168 материалов, 866 машин.

Если поиск по русскому слову из PowerShell 5.1 ничего не находит, выполните один раз `chcp 65001` — иначе консоль портит кодировку аргументов.
